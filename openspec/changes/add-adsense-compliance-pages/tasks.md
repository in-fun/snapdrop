## 6b. Adversarial review fixes

Applied after an adversarial review pass. Each defect was confirmed by reproduction before being fixed, and each fix was re-verified — but by static analysis, curl, and a VM harness driving the service worker's captured handlers, **not in a real browser**.

That distinction matters most for 6b.6 and 6b.7, which change service worker behaviour. A VM harness covers control flow; it does not cover real Cache API semantics, opaque or `opaqueredirect` responses, or navigation-request redirect modes. **Tasks 4.3, 4.4, 4.5, 7.4, and 7.6 are the gating browser verification for those two fixes and remain open.**

- [x] 6b.1 `404.html` links and asset paths made root-absolute. The body is served at every unresolvable path, so document-relative URLs broke at any depth (`/deep/nested/garbage` requested `/deep/nested/styles/pages.css`), leaving the page unstyled with five dead links.
- [x] 6b.2 `POST /` now answers `303 -> /` instead of falling through to the 404. `express.static` serves GET/HEAD only, so the Web Share Target lost the network fallback it had under the old catch-all redirect.
- [x] 6b.3 Corrected a false claim in `privacy.html` and `how-it-works.html`: the **server** mints the device identifier (`peer.js:135`) and the client caches it in `sessionStorage` (`network.js:225`), so it does not persist between visits. Both pages said the browser generated it and that it survived across visits.
- [x] 6b.4 Softened `privacy.html`'s "ad code never has access to your files" — a same-origin third-party script has the access any page script has. Replaced with what is actually true and checkable.
- [x] 6b.5 Fixed a self-contradiction in `privacy.html`: consent was described as both handled by a CMP and not yet in place. Now states plainly that the CMP is not yet deployed and no personalised advertising is served until it is.
- [x] 6b.6 `doNotCacheRequest` now strips query and fragment before matching. A visitor arriving at `/privacy?utm_source=…` or `?gclid=…` — i.e. anyone referred by an ad or search result — was pinning a stale policy into the versioned cache.
- [x] 6b.7 Error responses are no longer written to the cache. Unknown paths returning a real 404 (rather than the old redirect, which threw) made 404 bodies cacheable.
- [x] 6b.8 Footer links now carry anchor text in the markup, overwritten by localization on hydration. They shipped as empty elements — reproducing the exact "empty to a crawler" pattern this change was created to fix.
- [x] 6b.9 Added `rel=canonical` to the shell. `extensions: ['html']` made `/index` a third URL for it alongside `/` and `/index.html`.
- [x] 6b.10 Spec amended: the 404 body is exempt from the canonical requirement (canonicalising it would advertise arbitrary paths as indexable) and must be `noindex` with root-absolute paths; cache matching must ignore query strings; error responses must not be cached.
